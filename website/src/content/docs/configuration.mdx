mdt is configured through command-line flags and environment variables. There is no configuration file.

## Usage

```bash
mdt [path] [--max-file-size <bytes>] [--max-width <columns>] [--center] [--no-images]
    [--note-command <cmd>]
```

If no path is given, mdt opens the current directory. You can pass a directory to browse or a specific file to open directly. When given a file, mdt opens it immediately, roots the file tree at the file's directory, and selects the file in the tree.

## Reading from stdin

mdt can read markdown from standard input via pipes:

```bash
echo "# Hello World" | mdt
cat README.md | mdt
curl -s https://example.com/doc.md | mdt
```

You can also use `-` as the path argument to read from stdin explicitly:

```bash
mdt -
```

In stdin mode, mdt operates in read-only preview mode. The file tree, file finder, and editor are disabled. The `--max-file-size` flag still applies to piped input.

## CLI flags

| Flag                      | Description                                   | Default          |
| ------------------------- | --------------------------------------------- | ---------------- |
| `--max-file-size <bytes>` | Maximum file size in bytes that mdt will open | 5,242,880 (5 MB) |
| `--max-width <columns>`   | Maximum width in columns for rendered markdown | none (terminal width) |
| `--no-images`             | Never draw images; `![alt](src)` shows as `[image: alt]` | images on |
| `--center`                | Centre the text in the pane, where `--max-width` leaves room | text to the left |
| `--note-command <cmd>`    | Shell command a right-click makes a note with | no notes |

For example, to allow opening files up to 10 MB:

```bash
mdt --max-file-size 10485760
```

To wrap rendered markdown at 100 columns even on a wide terminal, similar to a `less` max width:

```bash
mdt --max-width 100
```

When the terminal (or preview pane) is narrower than the limit, mdt wraps to the actual available width. The limit applies to both the file preview and the live preview pane.

`:width <columns>` sets the same limit while mdt is running, `:width 0` (or `off`) takes it off again, and `:width` on its own says what is in force.

## Centring

By default the text sits against the left of the pane, as a pager does, so a width limit on a wide terminal leaves the right-hand side empty. `--center` puts the text in the middle of the pane instead:

```bash
mdt --max-width 100 --center
```

`:center` turns it on and off while running. It only shows when a width limit leaves something to centre in: without `--max-width` the text already fills the pane. The scrollbar stays at the pane's edge, and clicking a link or an image still lands where you see it.

## Environment variables

### `MDT_MAX_WIDTH`

Sets the default for `--max-width`. The flag takes precedence when both are given.

```bash
export MDT_MAX_WIDTH=100
```

### `NO_COLOR`

mdt respects the [NO_COLOR](https://no-color.org/) standard. Set this environment variable to any value to disable all color output:

```bash
NO_COLOR=1 mdt
```

This is useful for terminals that do not support colors or when piping output.

### `MDT_CENTER`

Set to `1` to start with the text centred, as if `--center` were given.

```bash
export MDT_CENTER=1
```

### `MDT_NOTE_COMMAND`

Sets the default for `--note-command`.

```bash
export MDT_NOTE_COMMAND=~/bin/my-note-script
```

### `MDT_NO_IMAGES`

Set to `1` to start with images off, as if `--no-images` were given.

```bash
export MDT_NO_IMAGES=1
```

## Terminal integration

### Inline images

`![alt](path)` is drawn in the preview: PNG, JPEG, GIF, WebP and BMP files, and SVG, which is rasterised at the size it is shown. At startup mdt asks the terminal what it can do and picks kitty's graphics protocol, sixels or iTerm2's, falling back to unicode half-blocks anywhere else (including through `tmux` without passthrough). Images are sized to the pane, never upscaled, and take at most 24 rows; one scrolled partly off the top or bottom shows the part that is on screen. Only local files are drawn — a remote URL shows as `[image: alt] (url)` and a missing file as `[image: alt] (not found)`.

Inline images are sized to be read alongside the text, so a big one is shown small. Press `I`, or click it, to open the viewer: the picture fills the screen, `+` and `-` (or the mouse wheel) zoom from the whole picture up to 8x, `h` `j` `k` `l` pan once you are in past the edges, `0` returns to the whole picture, `n` and `N` step through the document's images, and `esc` closes it.

Press `Ctrl+g` or run `:images` to turn images off and on for a busy page. (Not `Ctrl+i`: terminals send that as `Tab`, which switches panes.) `--no-images` (or `MDT_NO_IMAGES=1`) skips the terminal query entirely.


### Mouse support

mdt supports mouse input out of the box:

- **Scroll wheel** to scroll the preview or file tree
- **Click** to switch focus between panes
- **Click a link** in the preview to open it with your system handler
- **Click an image** in the preview to open it large in a zoomable viewer
- **Drag** over the preview to select text; `esc` clears it. Nothing goes to the clipboard — a selection is there to be read, and to be quoted in a note. Your terminal's own selection (shift-drag, in kitty) still works for copying
- **Right-click** the preview to make a note about the page, when `--note-command` is set

No configuration is needed; mouse support is enabled automatically.

### Taking notes

Drag over the text to select some of it, then right-click to open a box and say what you think. The comment wraps and takes as many lines as it needs, and Enter starts another line, so a note can be a few sentences rather than one.

| Key | Action |
| --- | ------ |
| `Ctrl+d` | Make the note |
| `Ctrl+e` | Write it in `$VISUAL`/`$EDITOR` instead, as markdown. mdt steps out of the way while the editor has the terminal; what you save is the note, and an empty file makes none |
| `esc` | Abandon it |

mdt runs `--note-command` through your shell and puts whatever it prints in the status bar — so a command that echoes the new note's name will say so, and one that fails says why.

mdt knows nothing about where notes go. The command is given what mdt does know, in its environment:

| Variable | What it is |
| -------- | ---------- |
| `MDT_NOTE_COMMENT` | What you typed into the box |
| `MDT_NOTE_SELECTION` | The text you dragged over, if any |
| `MDT_NOTE_REF` | The page's own id, where the page says what it is |
| `MDT_NOTE_FILE` | The file being read; empty when it came down a pipe |
| `MDT_NOTE_LINE` | The line that was right-clicked |

`MDT_NOTE_REF` comes from the metadata line a [quine](https://github.com/indeterminacy/homunculus) page carries under its title:

```markdown
# Why the room is the instrument

`essay` · 2025-09-21 · `room0`
```

The last backticked word there is the page's id. It is read from the page rather than the file, so it works for a page piped in from `quine read`, which has no file of its own. A page without that line leaves it empty, and the note has nothing to attach to.

The repository's `examples/quine-note.sh` is a working command for quine: it makes a note of the comment with the selection quoted beneath it, then links the note back to the page with `informed-by`.

### Background color detection

mdt detects your terminal's background color to prevent transparency bleed-through. This ensures that rendered elements like code blocks and tables look correct regardless of your terminal's color scheme.

### Width-aware rendering

mdt adapts its rendering to the terminal width:

- Paragraphs, headings, blockquotes, and lists wrap to fit the available space
- Code blocks and tables are truncated when the terminal is too narrow, rather than breaking the layout

### Performance

mdt is built for speed with several optimizations:

- **Dirty-flag rendering** -- only redraws the screen when something actually changes
- **Pre-warmed syntax highlighting** -- loads syntax definitions on a background thread at startup
- **Panic-safe terminal teardown** -- restores the terminal state even if mdt crashes unexpectedly
